# Админка новостей (Yangiliklar) — дизайн

Дата: 2026-09-09. Статус: утверждено, к реализации.

## Цель

Отдельная страница-админка, из любого браузера (включая телефон), которой
управляет один человек — владелец репозитория. Функции:

- создать пост;
- отредактировать текст и фотографии опубликованного поста;
- удалить пост;
- видеть количество просмотров каждого поста; счётчик показывается и публично
  на странице поста.

Сайт остаётся статическим. Источник правды — git. Бэкенда для контента нет:
админка пишет прямо в репозиторий `BekkiBay/ndu` через GitHub API, а
существующий CI собирает и выкатывает сайт. Единственный серверный компонент —
мини-сервис счётчика просмотров на Hermes, в том же compose-проекте
`ndu-static`.

## Принятые решения

| Вопрос | Решение |
|---|---|
| Откуда управлять | Из любого браузера: страница `admin/` на самом сайте, GitHub fine-grained token в `localStorage` |
| Состав поста | Заголовок, дата, анонс, обложка, текст с фото между абзацами, галерея под текстом |
| Редактор текста | Quill 2 (WYSIWYG), тело поста хранится как HTML |
| Главная | Карусель новостей на `index.html` = последние 6 постов, обновляется сборкой |
| Просмотры | Свой мини-сервис на Hermes (Python stdlib + SQLite), показывается в админке и на странице поста |
| Где публикуется | JSON в репо → `scripts/build_news.py` в CI → деплой собранного |
| Адрес админки | Пока `http://185.217.199.92:8083/admin/`; после появления домена и https — тот же путь на домене, код не меняется |

Черновики, несколько языков, категории, авторы — вне объёма. Блок
«Yaqinlashayotgan tadbirlar» на главной не трогаем: это события, не новости.

## 1. Данные

Файл `content/news.json`:

```json
{
  "posts": [
    {
      "slug": "yangi-laboratoriya-ochildi",
      "title": "Yangi zamonaviy laboratoriya ochildi",
      "date": "2026-09-07",
      "excerpt": "Kimyo fakultetida yangi laboratoriya ishga tushirildi.",
      "cover": "images/nsu/news/yangi-laboratoriya-ochildi/cover.jpg",
      "body": "<p>…</p><img src=\"images/nsu/news/yangi-laboratoriya-ochildi/01.jpg\"><p>…</p>",
      "gallery": ["images/nsu/news/yangi-laboratoriya-ochildi/g01.jpg"],
      "updated": "2026-09-09T12:00:00Z"
    }
  ]
}
```

Поля:

- `slug` — обязателен, уникален, `^[a-z0-9]+(-[a-z0-9]+)*$`, не длиннее 80
  символов. Страница поста — `news-<slug>.html`. Генерируется админкой из
  заголовка: lowercase, апострофы `ʻ ʼ ’ '` и модификаторы удаляются
  (`oʻquv` → `oquv`), всё остальное не-`[a-z0-9]` заменяется на `-`, дефисы
  схлопываются и обрезаются по краям. Slug можно править руками до первой
  публикации; после публикации поле заблокировано (смена slug = смена URL).
- `title` — обязателен, обычный текст, экранируется при вставке в HTML.
- `date` — `YYYY-MM-DD` или `null`. Для новых постов админка подставляет
  сегодняшнюю дату. `null` допустим только у импортированных постов: у них
  реальных дат нет (nsuz.uz их не публикует), выдумывать не будем.
- `excerpt` — обычный текст до 300 символов, показывается в карточке и в
  `<meta name="description">`. Может быть пустым.
- `cover` — обязателен, путь от корня сайта. Для новых постов —
  `images/nsu/news/<slug>/cover.jpg`. Импортированные посты ссылаются на
  существующие общие файлы `images/nsu/news/*.jpg`.
- `body` — HTML из Quill. Вставляется в страницу как есть: редактирует только
  владелец репозитория, санитайзер не является границей безопасности.
  Картинки в теле — `<img src="images/nsu/news/<slug>/NN.jpg">`, пути от корня
  сайта.
- `gallery` — массив путей, порядок = порядок показа. Может быть пустым.
- `updated` — ISO-время последнего сохранения из админки, информационное.

Файлы фотографий: папка на пост `images/nsu/news/<slug>/`. Обложка `cover.jpg`,
картинки в тексте `01.jpg`, `02.jpg`, …, галерея `g01.jpg`, `g02.jpg`, ….
Номер — следующий свободный в папке, при замене файл получает новый номер (без
перезаписи, чтобы кэш браузера не показывал старую картинку). Админка сжимает
фото на клиенте через canvas: длинная сторона ≤ 1600 px, JPEG quality 0.82.

Правило удаления файлов: админка удаляет из репозитория только файлы внутри
`images/nsu/news/<slug>/` собственного поста — при удалении поста целиком, при
замене обложки, при удалении картинки из галереи или из текста. Общие файлы
импортированных постов не трогаются никогда.

## 2. Сборка: `scripts/build_news.py`

Python 3, только стандартная библиотека. Запуск из корня репозитория, без
аргументов. Читает `content/news.json`, `contact.html` (донор оболочки) и
`index.html`. Пишет `news-<slug>.html` для каждого поста, `news.html` и
правит `index.html` на месте.

### Оболочка страницы

Оболочка (head, шапка, меню, подвал, скрипты) берётся из донора `contact.html`
при каждой сборке, поэтому любое изменение шапки или подвала на сайте
автоматически попадает в новости. Донор режется по двум маркерам, каждый должен
встретиться ровно один раз, иначе сборка падает с ошибкой, называющей маркер:

- начало контента: `<section id="sp-page-title"`;
- начало подвала: `<!-- ====== FOOTER`.

В голове донора подменяются `<title>`, `<meta name="og:title">`,
`<meta name="og:image">` и `<meta name="description">`. В меню у ссылки
`<a class="menu__link is-active" href="contact.html">` снимается `is-active`
(в доноре активна ссылка на контакты), а ссылке `<a class="menu__link"
href="news.html">` он добавляется. Класс `is-active` у переключателя языка
(`data-label="O‘zbekcha"`) не трогается.

### Страница поста `news-<slug>.html`

Внутри существующей разметки SP Page Builder (те же обёртки, что у нынешних
новостей, чтобы работали стили и отступы):

- hero `nsu-page-hero has-bg` с обложкой;
- крошки `Bosh sahifa / Yangiliklar / <title>` (ссылки на `index.html` и
  `news.html`);
- `<h1>` заголовок;
- строка мета `nsu-post-meta`: дата в узбекском формате (`7-sentabr, 2026`),
  затем `Ko‘rishlar: <span data-views="<slug>">…</span>`. Блок просмотров
  изначально `hidden` и показывается скриптом, когда счётчик ответил. Если даты
  нет — показывается только счётчик;
- тело поста как есть, обёрнутое в `<div class="nsu-post-body">`;
- галерея `nsu-post-gallery` (сетка, каждая картинка — ссылка на оригинал,
  `loading="lazy"`), только если массив не пуст;
- существующий CTA-блок «Savolingiz yoki taklifingiz bormi?» без изменений;
- перед закрытием `</body>` inline-скрипт счётчика (см. раздел 4).

`og:image` = обложка, `description` = анонс (или заголовок, если анонс пуст).

### Список `news.html`

Та же оболочка, hero с заголовком «Yangiliklar va e’lonlar» и подзаголовком,
как сейчас. Сетка `nsu-news-grid`, карточка `nsu-news-card`: обложка,
`nsu-news-tag` с датой (если даты нет — «YANGILIKLAR», как сейчас), заголовок,
анонс.

Сортировка везде одинаковая: сначала посты с датой по убыванию даты, при равной
дате — по `updated` по убыванию; затем посты без даты в порядке следования в
JSON.

### Карусель на `index.html`

Вокруг нынешних одиннадцати `<div role="article" class="sppb-articles-carousel-column">`
один раз руками ставятся маркеры `<!-- news:carousel -->` и
`<!-- /news:carousel -->`. Сборка заменяет содержимое между маркерами
карточками первых шести постов в той же разметке (обложка, заголовок, рубрика
«YANGILIKLAR» со ссылкой на `news.html`). Маркеры обязаны присутствовать ровно
по одному разу.

### Свойства

- Детерминирована: повторный запуск без изменений входных данных не меняет ни
  один файл (важно для проверки штампов в CI и чистого `git status`).
- Валидирует данные и падает с понятным сообщением: дубликат `slug`,
  недопустимый `slug`, отсутствие файла обложки или картинки галереи,
  неверный формат даты, отсутствующий или неоднократный маркер.
- Не трогает ничего, кроме `news.html`, `news-*.html` и блока между маркерами в
  `index.html`. Устаревшие `news-*.html` (пост удалён) сборка удаляет из
  рабочего каталога.

### Стили

Новые классы `nsu-post-meta`, `nsu-post-body`, `nsu-post-gallery` добавляются
в `assets/css/nsu.css` в палитре и шрифтах, которые уже используются
(`--nsu-primary`, `--nsu-muted`, `--nsu-border`). `nsu-post-body img` —
`max-width:100%; height:auto; border-radius:4px; margin:16px 0`.

### Git

`news.html` и `news-*.html` — артефакты сборки: удаляются из репозитория и
добавляются в `.gitignore`. `index.html` остаётся под контролем версий, потому
что содержит всё остальное содержимое главной; сборка правит только блок между
маркерами. Локальная разработка: `python3 scripts/build_news.py && python3 -m
http.server 8899`.

## 3. Админка `admin/`

Файлы: `admin/index.html`, `admin/admin.js`, `admin/admin.css`,
`admin/vendor/quill.js`, `admin/vendor/quill.snow.css` (Quill 2.0.3, вендорится
в репозиторий, внешних CDN нет). Ванильный JavaScript, без сборки.
Интерфейс на русском.

Админка живёт на сайте по адресу `<корень сайта>/admin/`. Корень сайта
вычисляется как `new URL('..', location.href)`, поэтому одна и та же страница
работает на `http://185.217.199.92:8083/admin/`, на будущем домене и на
GitHub Pages (`/ndu/admin/`), пусть на Pages и без счётчика.

### Вход

Экран с одним полем — GitHub fine-grained personal access token — и краткой
инструкцией: Settings → Developer settings → Fine-grained tokens; Repository
access: only `BekkiBay/ndu`; Permissions: Contents — Read and write,
Actions — Read (для статуса деплоя). Кнопка «Войти» проверяет токен запросом
`GET /repos/BekkiBay/ndu` и сохраняет его в `localStorage`. Кнопка «Выйти»
удаляет токен. Ответ 401 от GitHub в любой момент возвращает на экран входа.

### Список постов

Таблица: миниатюра обложки, заголовок, дата, просмотры, кнопки «Изменить» и
«Удалить». Кнопка «+ Новый пост». Порядок — как на сайте.

Просмотры берутся одним запросом `GET <корень сайта>/views/counts`. Если запрос
не удался (Pages, сервис лежит) — в колонке «—».

Вверху статус последнего деплоя: запрос
`GET /repos/BekkiBay/ndu/actions/runs?branch=main&per_page=1`, показывается
статус (`в очереди`, `выполняется`, `успешно`, `ошибка`) со ссылкой на прогон
и временем. Пока прогон не завершён, обновляется каждые 20 секунд. После
сохранения поста сразу показывается подсказка «Опубликуется через 1–2 минуты».

### Редактор поста

Одна форма, поля сверху вниз:

- Заголовок (обязателен).
- Дата (`<input type="date">`, по умолчанию сегодня).
- Slug: генерируется из заголовка на лету, пока пользователь его не правил
  руками; после первой публикации только для чтения. Проверяется на формат и
  уникальность среди других постов.
- Анонс (textarea, счётчик до 300 символов).
- Обложка: превью + кнопка выбора файла. Обязательна для публикации.
- Текст: Quill с панелью H2, H3, жирный, курсив, подчёркнутый, ссылка,
  нумерованный и маркированный список, цитата, картинка, очистка формата.
  Кнопка картинки открывает выбор файла, файл сжимается и вставляется в текст.
- Галерея: множественный выбор файлов, миниатюры, у каждой кнопка удаления и
  стрелки «выше/ниже».
- Кнопки: «Опубликовать», «Отмена»; в режиме редактирования ещё «Удалить пост»
  с подтверждением (`confirm` с названием поста).

Справа (на узком экране — под формой) живое превью: обложка, заголовок, дата,
тело и галерея в шрифтах и цветах сайта. Это приближение, не пиксельная копия
страницы.

Работа с картинками до публикации: выбранные файлы хранятся в памяти как Blob,
в редакторе и превью показываются через `URL.createObjectURL`. При сохранении
каждому назначается конечный путь `images/nsu/news/<slug>/…`, а в HTML тела
`blob:`-адреса заменяются на эти пути. Уже опубликованные картинки при
открытии поста показываются с сайта: относительные пути `images/…`
разрешаются от корня сайта, а при сохранении приводятся обратно к виду
`images/…`.

### Сохранение — один коммит

Любое действие (создать, изменить, удалить) — ровно один коммит в `main` через
Git Data API:

1. `GET /git/ref/heads/main` → sha головного коммита; `GET /git/commits/{sha}`
   → sha дерева.
2. `GET /contents/content/news.json?ref={sha}` → актуальный JSON. Изменение
   применяется к нему (не к копии, загруженной при открытии админки).
3. Для каждой новой картинки `POST /git/blobs` (base64).
4. `POST /git/trees` с `base_tree` = текущее дерево: `content/news.json`
   (новое содержимое), новые картинки, удаляемые файлы как записи с
   `sha: null`.
5. `POST /git/commits` (родитель — головной коммит), затем
   `PATCH /git/refs/heads/main` без `force`.
6. Если `PATCH` вернул 409 или 422 (кто-то запушил параллельно), весь цикл
   повторяется один раз с новой головы. Вторая неудача — сообщение
   пользователю, данные формы не теряются.

Сообщения коммитов: `news: add «<title>»`, `news: update «<title>»`,
`news: delete «<title>»`. Токен передаётся только в заголовке
`Authorization: Bearer` на `https://api.github.com`, никуда больше.

Валидация до отправки: заголовок, slug (формат, уникальность), обложка, дата
(если задана — валидная). Ошибки показываются рядом с полем, кнопка
«Опубликовать» блокируется на время запроса.

## 4. Счётчик просмотров

### Сервис `deploy/counter/counter.py`

Python 3.12, только stdlib: `http.server.ThreadingHTTPServer`, `sqlite3`,
`json`, `hashlib`. Один файл, конфигурация через переменные окружения
`COUNTER_DB` (по умолчанию `/data/views.db`) и `COUNTER_PORT` (8080).

Схема SQLite:

```sql
CREATE TABLE IF NOT EXISTS views (slug TEXT PRIMARY KEY, count INTEGER NOT NULL DEFAULT 0);
CREATE TABLE IF NOT EXISTS seen  (slug TEXT NOT NULL, visitor TEXT NOT NULL, day TEXT NOT NULL,
                                  PRIMARY KEY (slug, visitor, day));
```

Эндпоинты (nginx монтирует сервис под `/views/`, префикс срезается):

| Метод и путь | Что делает | Ответ |
|---|---|---|
| `POST /hit` тело `{"slug": "..."}` | Засчитывает просмотр: один на (slug, посетитель, UTC-сутки). Посетитель = `sha256(ip + user-agent)`, IP из `X-Forwarded-For` (первый адрес), иначе адрес соединения. Боты по User-Agent (`bot`, `crawl`, `spider`, `slurp`, `preview`, `headless`, `python-requests`, `curl`, `wget`, пустой UA) не засчитываются, но текущее значение получают | `{"slug": "...", "count": N}` |
| `GET /count/<slug>` | Текущее значение | `{"slug": "...", "count": N}` |
| `GET /counts` | Все значения | `{"<slug>": N, ...}` |
| `GET /health` | Живость | `ok` |

Правила:

- `slug` проверяется тем же регулярным выражением, что в сборке; иначе 400.
  Тело больше 1 КБ — 413. Неизвестный путь — 404. Сервис не знает список
  постов: любой валидный slug заводит строку; это ограничено форматом и длиной.
- Все ответы `application/json; charset=utf-8`, `Cache-Control: no-store`,
  `Access-Control-Allow-Origin: *`; `OPTIONS` отвечает на preflight (нужно на
  будущее, когда админка или Pages окажутся на другом origin).
- Таблица `seen` чистится от записей старше двух суток при старте и раз в час.
- Записи в SQLite под одним `threading.Lock`; база открывается с
  `check_same_thread=False`.
- Логи — одна строка на запрос в stdout (`docker logs`).

### Встраивание в сайт

`deploy/docker-compose.yml`: новый сервис `counter` — образ
`python:3.12-alpine`, `command: ["python", "-u", "/app/counter.py"]`,
`volumes: ./counter/counter.py:/app/counter.py:ro` и именованный том
`ndu-counter-data:/data`, `restart: unless-stopped`, порт наружу не публикуется.
Сервис `web` получает `depends_on: [counter]`.

`deploy/nginx-site.conf`: перед `location /`:

```nginx
location /views/ {
    proxy_pass         http://counter:8080/;
    proxy_set_header   X-Forwarded-For $remote_addr;
    proxy_set_header   Host $host;
    add_header         Cache-Control "no-store";
}
```

Страница поста получает inline-скрипт перед `</body>`:

```html
<script>
(function(){
  var el=document.querySelector('[data-views]');if(!el)return;
  fetch('views/hit',{method:'POST',headers:{'Content-Type':'application/json'},
    body:JSON.stringify({slug:el.getAttribute('data-views')})})
  .then(function(r){return r.ok?r.json():Promise.reject(r.status)})
  .then(function(d){el.textContent=d.count;el.closest('.nsu-post-views').hidden=false})
  .catch(function(){});
})();
</script>
```

Относительный адрес `views/hit` разрешается от корня сайта, поэтому одинаково
работает по IP, на будущем домене и молча не работает на Pages (там ответ 404,
блок просмотров остаётся скрытым).

## 5. CI/CD

Сборка детерминирована и занимает доли секунды, поэтому каждая задача
workflow собирает сайт сама после `checkout`, артефакты между задачами не
передаются.

`ci.yml`, задача `validate`, шаги по порядку:

1. `python3 -m unittest discover -s tests -v` — тесты сборки и счётчика.
2. Проверка штампов `?v=` на чистом checkout: `stamp_assets.py` и
   `git diff --quiet` (как сейчас; выполняется до сборки, чтобы сгенерированные
   и правленные сборкой файлы не давали ложный diff).
3. `python3 scripts/build_news.py`.
4. `python3 scripts/stamp_assets.py` — штампует сгенерированные страницы.
5. `python3 scripts/check_links.py`.
6. Инвентаризация, как сейчас.

`deploy.yml`:

- Задачи `deploy` и `pages` после `checkout` выполняют шаги 3–4 (сборка и
  штампы), затем делают то, что делали.
- Rsync сайта остаётся без `--delete`; к исключениям добавляются `content`,
  `tests` и `docs` (на сервере им делать нечего). Сразу за ним второй, точечный вызов
  удаляет с сервера только страницы удалённых постов:

  ```bash
  rsync -av --delete --include='news-*.html' --exclude='*' \
    -e "ssh -i ~/.ssh/deploy_key -p ${PORT:-22}" ./ "$USER@$HOST:$DEST/"
  ```

  Это единственное документированное исключение из правила «на сервере
  ничего не удаляем»; оно фиксируется в `deploy/README.md`.
- Синхронизация `deploy/` в `/opt/ndu-static/` переводится с трёх именованных
  файлов на каталог целиком (`rsync -avz --inplace deploy/ …`, без
  `--delete`), чтобы на сервер попадал `counter/counter.py`. Дальше
  существующие `docker compose -p ndu-static up -d`, `nginx -t` и
  `nginx -s reload` поднимают контейнер счётчика и новый `location`.
- Проверка `SITE_URL` дополняется запросом `GET $SITE_URL/views/health`,
  который должен вернуть 200.

`server-setup.sh` не меняется по смыслу; при первом запуске compose сам
создаёт том `ndu-counter-data`.

## 6. Тесты

Каталог `tests/`, стандартный `unittest`, без внешних зависимостей. Тесты
работают во временном каталоге с синтетическим донором и `index.html`, а не с
реальными страницами, чтобы не зависеть от их размера.

`tests/test_build_news.py`:

- `slugify`: апострофы разных видов, узбекские `oʻ`/`gʻ`, пробелы и знаки,
  схлопывание дефисов, обрезка по краям, ограничение длины.
- Формат даты: `2026-09-07` → `7-sentabr, 2026`, все 12 месяцев, `None` → пусто.
- Сортировка: даты по убыванию, при равных — `updated`, недатированные в
  конце в исходном порядке.
- Оболочка: маркеры, перенос `is-active` с контактов на новости, язык не
  тронут; отсутствие или дубликат маркера — `SystemExit` с текстом маркера.
- Страница поста: заголовок экранирован, обложка в hero и `og:image`, дата,
  `data-views`, тело как есть, галерея только при непустом массиве, скрипт
  счётчика присутствует.
- Список: порядок карточек, дата или «YANGILIKLAR», анонс.
- Карусель: заменяется только блок между маркерами, максимум шесть карточек,
  остальной `index.html` побайтно тот же.
- Валидация: дубликат slug, плохой slug, отсутствующая обложка, плохая дата.
- Идемпотентность: второй запуск не меняет ни один файл; устаревший
  `news-*.html` удаляется.

`tests/test_counter.py` (поднимает сервер на свободном порту с временной
базой):

- первый `POST /hit` даёт 1, повторный тем же посетителем в те же сутки — 1;
- другой User-Agent — 2; другой `X-Forwarded-For` — 3;
- бот по UA не увеличивает, но получает текущее значение;
- невалидный slug — 400, слишком большое тело — 413, неизвестный путь — 404;
- `GET /count/<slug>`, `GET /counts`, `GET /health`;
- заголовки `Access-Control-Allow-Origin` и `Cache-Control: no-store`;
- `OPTIONS` — 204 с CORS-заголовками.

Админка покрывается ручной проверкой по чек-листу в плане (вход, создание,
редактирование, удаление, картинки, статус деплоя); автотестов для неё нет.

## 7. Миграция существующих постов

Одноразовый скрипт `scripts/import_legacy_news.py` (остаётся в репозитории
как документация того, откуда взялись данные):

- читает нынешние `news.html` и одиннадцать `news-*.html`;
- для каждого поста берёт slug из имени файла, заголовок из `<h1>`, обложку из
  `background-image` hero, анонс из `<p>` карточки в `news.html` (если есть),
  тело — содержимое `sppb-addon-content` первой секции как есть;
- `date: null`, `gallery: []`, `updated` — время импорта;
- порядок постов в JSON — как в нынешнем `news.html`;
- пишет `content/news.json`.

После импорта старые страницы удаляются из git (`git rm news.html
news-*.html`), сборка генерирует их заново из JSON. URL всех одиннадцати
постов не меняются.

## Отклонения при реализации

- Имена файлов картинок несут метку времени сохранения
  (`20260909-161926-cover.jpg`, `…-01.jpg`, `…-g01.jpg`) вместо `cover.jpg`,
  `01.jpg`, `g01.jpg`: nginx кэширует картинки на 30 дней, и повторное
  использование имени после замены показывало бы посетителям старую картинку.
- `slugify` живёт только в `admin/slug.js` (с транслитерацией кириллицы);
  сборка на Python slug не генерирует, а только проверяет по `SLUG_RE`.
- Крошки на странице поста — `Bosh sahifa / Yangiliklar`, без заголовка:
  крошки набраны капителью, длинный заголовок в них не читается.
- Пустые абзацы из редактора не сохраняются: Quill оставляет их на месте
  удалённых картинок и строк.
- Quill 2.0.3 отдаёт пробелы как `&nbsp;`; админка возвращает обычные пробелы,
  иначе текст на сайте не переносился бы по словам.
